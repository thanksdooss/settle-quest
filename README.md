# Settle Quest

지역 대학에 온 외국인 유학생이 **지금 해야 할 행정 절차**를 순서대로 보여 주고, 서류 칸을 채워 주고,
**그 정보가 언제 확인된 것인지**까지 함께 보여 주는 웹 서비스입니다.

![규칙 검토 커버리지](https://img.shields.io/badge/90일_이내_확인-100%25-brightgreen)

> **행정 정보 안내이며 법적 효력이 없습니다.** 이 저장소는 공개된 공공 자료를 정리한 것입니다.
> 개인의 상황에 대한 판단을 대신하지 않습니다. 실제 신청 전에 관할 기관이나 외국인 종합안내센터(1345)에 확인하십시오.

## 왜 만들었나

3인 팀으로 유학생 46건(1차 16 + 2차 30), 이해관계자 31명을 인터뷰했습니다. 거기서 나온 말 하나가 이 제품의 설계를 결정했습니다.

> "학교 국제처에서 안내문을 주긴 했지만, **작년 정보인 것 같아 불안했다.**
> 결국 같은 나라에서 먼저 온 선배에게 연락해서 필요한 서류 목록과 방문 후기를 전부 들었다."

- 같은 관공서를 2번 이상 재방문한 응답자 **86.7%**
- 공식 채널보다 선배·지인 같은 비공식 경로에 의존 **76.7%**
- 유료 서비스 지불 의사 **80%**, 대표 구간 **건당 1~3만 원**

문제는 정보가 없는 것이 아니라 **믿을 수 있는지 알 수 없는 것**이었습니다.
사용자가 사는 것은 편리함이 아니라 확실성입니다. 그래서 이 제품은 **확실하지 않을 때 확실하지 않다고 말합니다.**

이 판단이 맞다는 증거는 만들면서 바로 나왔습니다.
외국인등록 제출서류를 안내하는 정부 공식 페이지는 스스로 **"작성일 2013.01.01"** 이라고 적어 두고 있었습니다.
학생들이 느낀 불안은 착각이 아니었습니다.

## 이 제품의 본질은 OCR이 아니라 정보 신선도

절차는 국적·비자·기관에 따라 갈리고 학기 중에도 바뀝니다. 코드에 박으면 사용자가 불평했던 그 문제를 그대로 재현합니다.

**1. 절차는 코드가 아니라 버전 있는 데이터입니다.** `rules/*.yaml` 한 파일이 절차 하나이고,
각 출처에 `출처 URL · 확인한 사람 · 확인일 · 다음 점검일 · 적용 조건`이 붙습니다. 버전 이력은 Git이 맡습니다.

**2. 상태는 사람이 적지 않고 날짜에서 계산합니다.**

| 상태 | 조건 | 화면 |
|---|---|---|
| `verified` | 확인일이 90일 이내 | "2026-09-21 확인" |
| `aging` | 90일 초과, 점검 기한 전 | 같은 표시 + 점검 예정일 |
| `stale` | 점검 기한 경과 | **"확인 필요" 배지 + 경고** |
| `changed` | 원문 해시가 달라짐 | **"확인 필요" + 검토 큐 등록** |

`status`를 데이터에 적는 것은 빌드 단계에서 **거부**됩니다. 그래야 아무도 손대지 않을 때 상태가 저절로 나빠집니다.

**3. `stale`인 절차를 목록에서 숨기지 않습니다.** 경고를 달아 그대로 보여 줍니다. 틀린 답보다 "모른다"가 낫습니다.

**4. 원문 변경을 감지하면 규칙을 고치지 않고 사람을 부릅니다.**
주간 배치가 각 출처를 받아 본문을 정규화·해시하고, 달라지면 `changed_at`을 찍고 검토 큐에 올립니다.
사람이 확인해 `checked_on`을 올릴 때까지 화면에는 "확인 필요"가 남습니다.

## 지금 들어 있는 것

절차 7개, 출처 11건. 전부 직접 원문을 열어 확인했습니다.

```
여권·비자 (전제)
   ├─→ 외국인등록 ──┬─→ 체류지 변경 신고
   │                ├─→ 국민건강보험 가입 (가입일 = 외국인등록일)
   │                ├─→ 시간제 취업 허가
   │                └─→ 외국인등록증 재발급·분실 신고
   ├─→ 휴대전화 개통   (선불은 여권만, 후불·알뜰폰은 외국인등록증)
   └─→ 은행 계좌 개설  (신분증명서 — 지점마다 다를 수 있음)
```

출처는 법무부 하이코리아와 법제처 찾기쉬운 생활법령정보(외국인유학생 편)입니다.

## 개인 문서를 다루는 원칙

- **서버가 없습니다.** 정적 PWA입니다. 여권 이미지를 보낼 곳 자체를 만들지 않았습니다.
- 여권은 **MRZ(기계판독영역)만** 읽습니다. 얼굴면 전체 OCR은 하지 않습니다.
  MRZ에는 체크디지트가 있어 **판독 결과를 스스로 검증**할 수 있기 때문입니다. 일반 OCR은 틀려도 그럴듯한 값을 내놓습니다.
- **판독 오류를 기계가 고치지 않습니다.** 고쳐 읽을 후보를 제안만 하고, 적용은 사용자가 누를 때만 합니다.
  (왜 자동 교정을 버렸는지는 [docs/decisions.md](docs/decisions.md) D-008에 있습니다. 테스트가 설계를 바꾼 사례입니다.)
- **한글 성명을 자동으로 만들지 않습니다.** 음차가 틀리면 서류가 반려됩니다. 사용자가 직접 입력합니다.
- 이미지는 캔버스에서만 다루고 저장하지 않습니다. 남는 것은 사용자가 확인한 텍스트뿐이며, 내보내기·삭제 버튼이 있습니다.

## 하지 않기로 한 것

원기획에는 검증된 행정사·공인중개사를 연결하고 중개 수수료를 받는 수익 모델이 있었습니다.
**금전 중개는 법적 검토가 필요해 제품에서 뺐습니다.** 대신 공개된 **공공 지원 창구 정보**만 정리해 보여 줍니다.

## 실행

```bash
npm install
npm run dev
```

| 명령 | 하는 일 |
|---|---|
| `npm run rules:build` | YAML 검증 후 앱이 읽는 번들 생성 (검증 실패 시 빌드 중단) |
| `npm run rules:check` | 원문 변경 감지 → `docs/review-queue.md` |
| `npm run rules:coverage` | 90일 이내 확인 비율 계산 → README 배지 |
| `npm test` | 규칙 엔진·신선도·MRZ 단위 테스트 |
| `npm run e2e` | 프로필 입력 → 절차 목록 → 서류 자동 채움 |
| `npm run privacy` | 빌드 결과물에 비공개 정보가 없는지 검사 |

## 규칙을 고치는 법

1. `rules/<절차>.yaml`을 고칩니다.
2. 확인한 출처의 `checked_on`을 오늘로, `next_check_on`을 90일 뒤로 바꿉니다.
3. `changed_at`이 있으면 지웁니다. 지우지 않으면 화면에 "확인 필요"가 계속 남습니다. 의도한 동작입니다.
4. `npm run rules:build && npm test`

## 한계

- 절차 7개, 비자 2종(D-2 · D-4)만 다룹니다.
- 기관·지점에 따라 요구 서류가 다른 경우가 실제로 보고됩니다. 규칙에 그 사실을 적어 두었지만 지점별 데이터는 없습니다.
- 변경 감지는 페이지 본문 해시 비교입니다. 문구만 바뀌어도 "확인 필요"가 뜰 수 있습니다. 놓치는 것보다 낫다고 보았습니다.
- 서식 자동 채움은 입력값을 보관·출력하는 수준입니다. 공식 서식 PDF는 재배포하지 않습니다.
